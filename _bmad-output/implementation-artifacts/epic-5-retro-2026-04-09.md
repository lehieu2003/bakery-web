# Epic 5 Retrospective - Customer Notifications & Read State

Date: 2026-04-09  
Project: bakery-web  
Epic: 5 - Customer Notifications & Read State

## Epic Outcome Summary

- Stories completed: 2/2
  - `5-1-event-driven-notification-delivery`: done
  - `5-2-notification-inbox-and-read-state-management`: done
- Epic objective status: achieved
  - Event-driven notification delivery implemented with retry/fallback and idempotency controls.
  - Customer inbox read-state lifecycle delivered with deterministic query behavior and route/service regression coverage.

## What Went Well

- Strong contract discipline:
  - Notification APIs preserved standardized `success/data/error` envelopes through refactors.
- Reliability guardrails improved:
  - Callback transition race-safety and dispatch sanitization fixes were applied during review hardening.
- Test depth increased in critical areas:
  - Route-level and service-level notification tests were added for authorization, read-state idempotency, and mark-all behavior.
- Fast review/repair loop:
  - Findings from code review were converted into concrete patches and regression tests in the same cycle.

## Challenges Observed

- Review execution overhead:
  - Multi-layer review artifacts introduced extra operational steps because subagent execution was constrained in-session.
- Environment-level test gap:
  - `npm test` remains partially blocked by a pre-existing Vitest/jsdom ESM worker issue (node tests pass; vitest worker startup fails).
- Story status synchronization risk:
  - Sprint-status transitions needed explicit manual updates at several points to remain aligned with implementation state.

## Key Lessons Learned

1. Build testability seams in route handlers early.
   - Dependency-injected handlers made read-state behavior easier to test and safer to evolve.
2. Add deterministic ordering explicitly on paginated customer feeds.
   - Tie-breakers avoid unstable UI ordering and reduce edge-case regressions.
3. Treat code review findings as backlog work items immediately.
   - Converting findings into tests + fixes in one pass reduced re-open risk.
4. Keep temporary review artifacts out of production commits by default.
   - Prompt/diff helper files are useful operationally but should remain untracked unless explicitly required.

## Technical Debt and Risks Carried Forward

- Open tooling debt:
  - Vitest worker compatibility issue with current jsdom/ESM path remains unresolved.
- Process debt:
  - Sprint status relies on manual updates for some transitions (risk of drift if skipped).
